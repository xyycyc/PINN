| 发现与影响 | 修复与边界 | 主要验证 |
| --- | --- | --- |
| 数字留空后保存为 `null`，再次启动转换整数时崩溃 | R5 已批准：保存要求补全数字，坏配置逐字段恢复；保留有效设置并在 GUI 日志提示，保存前不改原文件 | 配置回归；真实 GUI 留空保存、纠正保存、坏配置重载 |
| 保存成功后旧错误提示残留；新增清理提示代码对非命令页调用了不存在的方法 | 成功保存只清除支持该接口的页面提示；真实窗口模拟发现并修复该回归 | GUI 成功保存、页面切换与无回调异常 |
| GUI 强制要求验证集，CLI 支持无验证集训练 | R6 已批准：默认关闭「允许无验证集训练」；仅放行单数据集缺少验证集的情况，已有验证集和集合规则不变 | GUI 开关前后生成命令与保存值 |
| 手动校验时清空路径仍会触发 CLI 的自动发现 | 手动模式要求明确存在的清单文件，定位输入框；自动模式保留 | GUI 空路径不启动任务 |
| 清理只识别一层增量依赖，可能遗漏后代 | 扫描建立依赖图，遍历完整链，处理分支与循环；多目标共用依赖索引 | 基础模型、子代、孙代的删除与保留；循环元数据 |
| 报告时间戳可包含越界路径；合法文件名中的方括号被当成 glob 模式 | 验证单个路径组件和各配置目录边界，删除时再次检查；报告名按字面前缀匹配 | 越界时所有临时文件保持不变；同目录其他报告保留 |
| 相似模型名的前缀会重叠，共享训练摘要可能不属于被删模型 | 更长的其他模型名称优先认领报告；共享摘要只有确认属于当前模型或完整组时才清理 | `model.pt` 与 `model_copy.pt` 共存，其他模型和报告保留 |
| 保留增量时可能覆盖已有目标，且清除基础引用后丢失继承配置 | 先检查全部目标，拒绝重名；保存继承配置并逐个处理模型，避免同时持有全部权重 | 目标冲突在任何移动前失败；保留后配置和张量一致；报告可再次被清理识别 |
| 清理改写规则 CSV 直接覆盖文件并丢弃扩展列 | 完整临时文件原子替换，保留扩展列 | 模拟替换失败后原文件字节不变 |
| 增量输出与基础权重同名或与旧输出冲突时覆盖文件 | 在训练和创建报告前拒绝冲突 | 基础文件字节不变；已有权重与报告均受保护 |
| 增量基础引用为相对路径时按进程工作目录解析 | 相对引用跟随 checkpoint 所在目录；绝对路径不猜测盘符映射 | 不同目录下的相对基础引用，含 NumPy 元数据的旧模型 |
| 小数参数允许 NaN/无穷大，可能产生无效训练结果 | CLI 拒绝非有限值；训练核心权重与学习率、固定节点标准化也检查有限性 | 参数化 CLI 和后端回归，错误在训练前出现 |
| 错误 JSON 顶层或 records 类型导致 AttributeError/TypeError | 数据加载与划分提供明确结构错误；自动发现跳过坏候选 | 错误清单与有效旧候选共存的回归 |
| 升级 PyTorch 后省略加载模式可能不再兼容已有 checkpoint 字典 | 显式使用项目原有可信 checkpoint 加载模式，保持模型版本和格式 | 旧模型元数据读取；原模型训练/预测测试继续通过 |
| E 盘项目缺少必需的 Fortran DLL，单独 pip 安装无法补齐 | 使用现有编译器从仓库源码构建，增加环境自检并补全部署说明 | 实际 DLL 的 MAE/RMSE/最大误差和波形平均检查 |

PyTorch 加载默认值变化依据[官方 2.6 序列化说明](https://docs.pytorch.org/docs/2.6/notes/serialization.html#torch-load-with-weights-only-true)。项目 checkpoint 包含 NumPy 等元数据，因此显式保持 `weights_only=False`；使用范围限于项目生成或确认可信来源的模型。没有把已有权重转换成新格式。
